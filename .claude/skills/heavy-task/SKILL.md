# 큰 작업: 끊김 대비 절차

대화는 한도 소진으로 언제든 끊길 수 있다. 진행 상태는 프로젝트 루트의 `progress.json`과 git에만 남긴다.

**`progress.json`은 직접 읽거나 편집하지 않는다.**
- 조회와 수정은 모두 `.claude/bin/progress.sh`로 한다.
- 이 명령은 필요한 줄만 출력하므로 파일 전체를 읽을 필요가 없다.
- JSON 형식이 깨질 위험도 없다.

| 할 일 | 명령 |
|---|---|
| 새로 만들기 | `.claude/bin/progress.sh init "<작업명>" "<목표>" "1:<제목>" "2:<제목>" ...` |
| 현재 상황 (요약·진행 중·최근 메모) | `.claude/bin/progress.sh status` |
| 단계 목록 전체 | `.claude/bin/progress.sh steps` |
| 단계 완료 (다음 단계 자동 시작) | `.claude/bin/progress.sh done <id>` |
| 단계 막힘 (다음 단계 자동 시작) | `.claude/bin/progress.sh block <id> "<이유>"` |
| 특정 단계로 전환 | `.claude/bin/progress.sh start <id>` |
| 단계 추가 | `.claude/bin/progress.sh add <id> "<제목>" [<이 id 뒤에>]` |
| 메모 추가 | `.claude/bin/progress.sh note "<내용>"` |
| 작업 완료 (파일 삭제) | `.claude/bin/progress.sh finish` |

## 시작
1. `init`으로 만든다.
   - 단계는 하나에 30분 이내가 되도록 나눈다.
   - 첫 단계는 자동으로 진행 중이 된다.
2. 커밋한다: `chore(progress): start <작업명>`

## 진행
- 단계 하나를 마칠 때마다 바로 커밋한다.
  1. `done <id>`로 완료 처리한다.
  2. 그 변경까지 포함해 커밋한다.
  - 메시지 형식: `<type>(<id>): <요약> — next: <다음 할 일>`
- 단계가 예상보다 크면 `add`로 하위 단계를 끼워 넣는다. 예: `add 2-1 "<제목>" 2`
- 중간에 멈추면 깨지는 변경은 한 단계 안에서 끝낸다. 깨진 상태로 커밋해야 한다면 메시지를 `wip:`로 시작하고 깨진 이유를 적는다.
- 코드에 드러나지 않는 결정이나 막힌 점은 `note`로 한 줄 남긴다.
- 같은 문제로 두 번 실패하면 `block <id> "<이유>"`를 실행하고 커밋한 뒤 다음 단계로 간다.

## 한도 정보가 주어졌을 때
- 80% 이상: 남은 단계를 `add`로 더 잘게 나누고, 커밋 간격을 줄인다.
- 90% 이상: 새 단계를 시작하지 않는다. 대신 아래 순서로 마친다.
  1. 진행 중인 단계를 가장 가까운 완결 지점에서 멈춘다.
  2. 커밋한다.
  3. `note "다음 세션: <할 일>"`을 남긴다.
  4. 커밋한 뒤 종료한다.

## 재개 ("중단된 큰 작업" 정보가 주어졌을 때)
- `status`와 `git log --oneline -5`로 어디까지 했는지 확인한다.
  - 단계 전체가 필요할 때만 `steps`를 실행한다.
- 진행 중 단계부터 이어서 한다. 처음부터 다시 하지 않는다. 사람에게 진행 상황을 묻지 않는다.
- 메모에 `[auto]` 줄이 있으면 직전 세션이 갑자기 끊긴 것이다.
  - 마지막 `wip:` 커밋에 미완성 변경이 들어 있다.
  - 먼저 `git show --stat HEAD`로 범위를 확인한다.

## 끝
- 테스트와 빌드를 통과시킨다.
- `finish`를 실행하고 커밋한다: `chore(progress): done <작업명>`
- 파일이 남아 있으면 다음 세션이 미완료 작업으로 인식한다.
