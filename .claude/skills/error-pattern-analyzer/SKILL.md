# Error Pattern Analyzer — 오답 패턴 분석

## 1. 확신도 × 정오 매트릭스 (가장 먼저 본다)

풀이할 때 확신도(`sure` 확실 / `unsure` 애매 / `guess` 찍음)를 함께 기록한다.

|  | 맞음 | 틀림 |
|--|------|------|
| **확실** | 숙달 — 복습 간격 크게 늘림 | 🔴 **잘못 굳은 개념** — 최우선. confusions.md 대상 |
| **애매** | 🟡 불안정 — 헷갈리는 개념 후보 | 🟡 부분 이해 — 개념 재확인 |
| **찍음** | 🟡 **숨은 구멍** — 맞았어도 오답처럼 취급 | 지식 부재 — 개념 노트부터 |

## 2. 오답 원인 5-Type

| Type | 정의 | 판단 신호 | 처방 |
|------|------|----------|------|
| 🔴 개념 결손 | 개념을 잘못 알고 있음 | 확신 오답, 같은 개념 문항 반복 오답 | 개념 노트 재학습 → 셀프 체크 → 같은 개념 신규 문항 |
| 🟡 절차 오류 | 개념은 알지만 적용 단계에서 틀림 | 시나리오(apply/analyze)만 틀리고 remember는 맞음 | 판단 체크리스트 작성, 시나리오 문항 반복 |
| 🟢 부주의 | 알지만 실수 | 같은 문항 맞았다 틀렸다, 짧은 소요 시간, 조건어(NOT, 가장 저렴한) 놓침 | 조건어 밑줄 습관, 선택지 전부 읽기 |
| 🟡 함정 | 매력적 오답에 반복적으로 빠짐 | 여러 회차에서 **같은 오답 선택지**를 고름 | confusions.md 판별 규칙 추가 |
| ⚪ 지식 부재 | 처음 보는 내용 | 찍음 + 오답, 개념 노트에 해당 내용 없음 | concept-writer에 보강 요청 |

한 오답에 여러 신호가 겹치면 위 표의 위쪽 Type을 우선한다.

## 3. 개념 결손 체인

1. 오답 문항의 `concepts`를 모아 개념별 오답 수를 센다.
2. 오답 개념들의 **선수 개념**(리서치 개념 맵)을 따라 올라간다. 선수 개념의 문항도 틀렸다면 그 선수 개념이 뿌리다.
3. 뿌리 개념 → 영향받은 문항 목록으로 적는다: `[MTU](concepts.md#mtu) → q002, q045, q101`

## 4. 보완 우선순위

`우선순위 점수 = 영향 문항 수 × 2 + 확신 오답 수 × 3 + 개념 중요도(★1~3)`

점수 순으로 정렬해 상위 5개만 처방한다. 처방은 실행 가능한 행동으로 쓴다:
- ✗ "NAT 게이트웨이 공부하기"
- ✓ "concepts.md#nat-gateway 읽기 → confusions.md#nat-gw-vs-nat-instance 셀프 체크 → 대화형으로 nat-gateway 문항 5개"
